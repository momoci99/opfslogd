opfslogd 설계 총정리

2026-11-01 기준 · v0.1.0 배포 · 결정 #001 ~ #081 · 단계별 진행은 index.html

opfslogd는 브라우저 로그를 기기의 OPFS에 저장하는 라이브러리입니다. 이 페이지는 지금까지의 설계와 결정을 한곳에 모은 요약입니다. 자세한 설명은 각 설계 문서와 docs/decisions.md에 있습니다.

1. 목표

앱을 느리게 하지 않는다

log()는 1µs 미만, 예외를 던지지 않음. 파일 쓰기는 Worker에서.

로그를 잃지 않는다

페이지 이동, 탭 닫기, 브라우저 강제 종료에도 ack 받은 기록은 남음.

여러 탭에서 안전하다

탭마다 자기 파일만 씀. 한 탭만 해야 하는 일은 Web Locks로 고름.

단순하다

런타임 의존성 없음. 옵션은 꼭 필요한 것만. 조건 붙은 규칙을 만들지 않음.

대상은 최신 Chromium 계열, Firefox, Safari입니다. 데스크톱 세 엔진에서 테스트했고 모바일은 아직 검증하지 않았습니다. 요구사항과 성능 목표는 architecture.html에 있습니다.

2. 구조

  • 탭마다 Dedicated Worker 하나가 자기 active/ 파일을 createSyncAccessHandle()로 씁니다. 파일을 탭끼리 나누지 않으니 쓰기에 Lock이 필요 없습니다(#006).
  • 여러 탭 중 하나만 할 일(retention, 주인 없는 파일 복구, 업로드)은 Web Locks를 실행할 때만 ifAvailable로 잡고 바로 놓습니다. 탭 상태에 따른 조건은 없습니다(#022).
  • 탭 Lock을 쥔 동안만 그 탭의 active/ 파일은 주인이 있습니다. Lock이 없는 active/ 파일은 죽은 탭의 것이므로 복구해서 pending/으로 옮깁니다(#012, #020).
  • Worker는 별도 파일(worker.js)이고 new Worker(new URL('./worker.js', import.meta.url))를 그대로 씁니다. 번들러가 못 찾으면 workerUrl로 넘깁니다. 인라인 빌드는 하지 않습니다(#009, #059, #081).

자세히: architecture.html

3. 쓰기 경로

  1. log()가 그 자리에서 레코드를 JSON 한 줄로 만듭니다(#014). 직렬화할 수 없는 값은 {"_unserializable": ...}로 바꾸고 예외는 던지지 않습니다(#011).
  2. 줄은 메인 스레드의 문자열 큐에 쌓입니다(#015). 큐와 응답 안 온 양을 합쳐 상한(4M자)의 80%를 넘으면 debug·info를, 100%면 전부 거절합니다(#018, #019).
  3. flush 조건: 50ms 타이머, 256K자, error 기록(50ms 간격), 페이지 hidden과 pagehide(#017, #020, #077).
  4. Worker가 한 묶음을 쓰고 ack합니다. 매번 handle.flush()를 부르지는 않고, 세그먼트를 닫을 때만 부릅니다(#074).
  5. 쓰기가 실패하면 원인과 상관없이 파일을 쓰기 전 길이로 되돌리고, 실패 ack를 보내고, 로테이션합니다. 일부만 쓰인 쓰기는 용량 부족으로 봅니다(#064).
  6. 버린 기록은 flush마다 사유별로 한 줄("opfslogd: records dropped")로 남깁니다. 사유는 overload, quota, write-failed, retention입니다(#019, #044, #070).

tabId와 seq는 메인 스레드가 정하고, 레코드 줄은 모두 메인의 flush에서 나옵니다(#061). 자세히: protocol.html

4. 파일과 생애

  • 파일 이름: active/{startTs}_{tab}.seg, 닫힌 뒤 {minTs}_{maxTs}_{tab}.seg. 시각은 13자리이고 레코드 ts의 최솟값·최댓값입니다(#012, #067). 이름이 겹치면 maxTs를 1ms 올립니다(#075).
  • 내용: JSON 헤더 한 줄 {"format":1,"minReader":1,"tab","seq0","context"} + 레코드 JSON Lines. 바이너리 프레임과 CRC는 없습니다(#016, #071).
  • 레코드: ts, lv, msg, ctx, err(#011). Error는 name, message, stack, 자기 속성, cause 5단계까지(#025 ~ #027).
  • 내보낸 줄(upload, export, subscribe): 레코드에 tab, seq, 전역 context를 붙인 JSONL(#033, #042).
  • 크래시 복구: 마지막 완전한 줄 뒤를 잘라냅니다. 불완전한 줄, NUL, 잘못된 UTF-8, ts 없는 줄에서 멈춥니다(#016). 기록이 없는 파일은 지웁니다(#075, #078).
  • 버전: 헤더의 minReader가 이 라이브러리보다 새로우면 손대지 않고 unreadable-file로 한 번 알립니다(#013).
  • retention: 닫힌 파일을 기간(7일)과 전체 크기(50MB) 기준으로 지웁니다. 크기 기준은 done/부터, 오래된 것부터입니다(#050 ~ #053, #078).

자세히: storage-format.html

5. 공개 API

import { init, logger, setContext, flush, close, subscribe, exportLogs } from 'opfslogd'

init({
  namespace: 'my-app',                 // [a-z0-9_-]{1,64}, 기본 'default'
  context: { app: 'web', version },    // 내보낸 줄마다 붙는 전역 context
  rotate: { maxAgeMs: 300_000 },
  retention: { maxBytes: 50_000_000, maxAgeMs: 7 * 86_400_000 },
  upload: { send: (file, meta) => fetch(url, { method: 'POST', body: file, signal: meta.signal }),
            intervalMs: 60_000, timeoutMs: 60_000 },
  onError: (e) => report(e.code),
  workerUrl,                           // 번들러가 worker.js를 못 찾을 때만
})

logger.info('saved', { id })           // debug / info / warn / error(msg, ctx?)
logger.error('failed', { err })        // 또는 logger.error('failed', err)
setContext({ page: 'home' })           // 얕은 병합, undefined는 삭제, 새 세그먼트 시작
await flush()                          // Promise<boolean>, 디스크에 쓰였으면 true
const off = subscribe((records) => {}) // 디버깅용
const { file, skipped } = await exportLogs({ from, to })
await close()                          // 이후 log()는 버림
  • 모듈 싱글톤: init() 전에 남긴 기록은 큐에서 기다립니다(#028). 두 번째 init()은 경고 한 번과 함께 무시합니다(#029).
  • 실패해도 앱은 멀쩡: OPFS를 못 쓰면 닫힘 상태처럼 동작합니다(#041). 브라우저 페이지가 아니면(SSR) 아무것도 하지 않습니다(#062).
  • 업로드: send()가 resolve되면 done/, reject나 timeout이면 다음 주기에 재시도합니다. 한 번 실행은 첫 실패에서 멈추고, 전달은 at-least-once이므로 meta.segmentId로 중복을 거릅니다(#045 ~ #049, #079).
  • export: 닫힌 세그먼트와 이 탭의 활성 세그먼트를 시간순으로 병합합니다. 다른 탭의 활성 세그먼트는 빼고 skipped에 셉니다(#054 ~ #056, #080).
  • 오류 코드: opfs-unavailable, worker-load-failed, quota-exceeded, write-failed, worker-unresponsive, unreadable-file, invalid-option. onError가 없으면 코드마다 한 번 console.error(#040).
  • 일부러 뺀 것: query API(#057), 최소 레벨 옵션(#069), persist() 옵션(#065), 별도 drop 콜백(#039), 압축.

자세히: api.html, 사용법은 README.md

쓰기 경로

#결정상태
014log() 때 바로 직렬화유지
015메인 버퍼는 ring buffer가 아니라 문자열 큐유지
017flush 조건: 타이머(초안 200ms), 256K자, error(50ms 간격)유지 (주기는 #077)
018Worker가 flush마다 ack, 상한은 큐 + 응답 안 온 양유지
019과부하: 80%에서 debug·info 거절, 100%에서 전부, flush마다 drop 줄유지
020hidden과 닫기 때는 flush만, pending 이동은 주인 없는 파일 복구에 맡김유지
021크기와 시간으로 로테이션, 시간은 공개 옵션유지
061tabId와 seq는 메인이 정함, 레코드 줄은 모두 메인 flush에서유지
064쓰기 실패는 되돌리기, 실패 ack, drop 집계, 로테이션 (일부만 쓰이면 용량 부족)유지
070drop 줄은 flush마다 사유별 한 줄, from/to는 잃은 기록의 시간 범위유지
074handle.flush()는 세그먼트를 닫을 때만유지
076ack 끊김 10초, close()는 5초 뒤 포기, 쓰기 실패 뒤 flush()는 false유지
077flush 주기 50ms유지

공개 API

023subscribe()를 v0.1에 포함, flush 묶음을 받음유지
024메시지가 먼저, 그다음 선택적 ctx 객체유지

027err에 Error 자기 속성도 저장유지
028모듈 싱글톤 + init(), init 전 기록은 큐에서 대기유지
029두 번째 init()은 경고 한 번과 함께 무시유지
030close(): flush, pending 이동, 정지, 이후 기록은 버림유지
031전역 context는 바꿀 수 있고, 바뀌면 새 세그먼트유지
032setContext(partial)는 얕은 병합, undefined는 삭제유지
033내보낸 줄은 전역 context를 context 아래에유지
035내부 기본값 중 세그먼트 시간 상한만 공개 옵션유지
036그 옵션 이름은 rotate.maxAgeMs유지
038flush(timeoutMs?)는 Promise<boolean>유지
039별도 drop 콜백 없음유지
040내부 오류는 onError로 OpfslogdError와 code유지
041저장소를 못 열면 닫힘 상태처럼 동작유지
042subscriber는 내보낸 줄 모양의 객체를 받음유지
043subscribe는 해제 함수를 돌려줌, 용도는 디버깅유지
044drop 줄의 msg와 ctx.reason은 고정된 계약유지
057v0.1에 query API 없음유지
062브라우저 페이지가 아니면 아무것도 하지 않음유지
063실행 중이 아닐 때 exportLogs()는 바로 빈 결과유지
065persist() 옵션 없음, 앱이 직접 호출유지
069최소 레벨 옵션 없음, 기록 여부는 호출하는 쪽이 정함유지

업로드

#결정상태
045send()는 meta.signal을 받고 upload.timeoutMs 뒤 중단유지
046실패는 고정 주기로 재시도, 한 실행은 첫 실패에서 멈춤유지
047한 실행에서 올리는 세그먼트 수 제한 없음 (부하 시험 뒤 재검토)유지
048send(file, meta): JSONL Blob, segmentId, sha256, size, from, to, signal유지
049첫 업로드는 init() 직후 page idle 때, 그다음 1분마다유지
068탭마다 upload 설정이 다르면 세그먼트를 닫는 탭의 설정을 따름유지
079구현 세부: Lock과 send()는 메인, 변환과 해시는 Worker, 새 포맷 파일은 한 번만 알림유지

보존 (retention)

#결정상태
050retention은 크기 상한과 기간 상한유지
051retention.maxAgeMs 기본 7일유지
052retention.maxBytes 기본 50MB, 공개 옵션유지
053업로드 전 첫 idle 때 한 번, 그다음 1분마다 (내부)유지
078구현 세부: 기록 없는 주인 없는 파일은 지움, 쓰기와 나란히 실행, 시점은 메인이 정함유지

내보내기 (export)

#결정상태
054닫힌 세그먼트 + 호출한 탭의 활성 세그먼트유지
055exportLogs({ from?, to? })는 { file, skipped }유지
056탭을 가로질러 시간순으로 병합유지
080구현 세부: 활성 세그먼트는 메시지 순서대로 복사, 결과는 1M자마다 Blob으로 접음유지

9. 1.0까지 남은 것
