지금까지 확정된 것 (요약)

  • 대상: 최신 데스크톱 + 모바일 브라우저. 초당 수천 건 이상. 목표 수치는 성능 목표 참고.
  • 탭마다 Dedicated Worker가 sync access handle로 자기 세그먼트에 씁니다. SharedWorker는 쓰지 않습니다.
  • 여러 탭 중 하나만 해야 하는 일(보존 정리, 업로드, 주인 없는 파일 복구)은 Web Locks로 조율합니다. 업로드와 보존 정리 Lock은 실행할 때만 잡고 바로 놓습니다. 탭 상태에 따른 조건은 없습니다(#022).
  • 업로드는 사용자가 넘기는 send() 콜백으로 합니다. resolve되면 done, reject되면 재시도합니다.
  • 세그먼트 상태: active → pending → done → 삭제. 크기(8MB)나 시간(초안 5분, 옵션 rotate.maxAgeMs)이 차면 로테이션합니다(#021, #036). 탭이 닫힐 때는 pending으로 옮기지 않고 주인 없는 파일 복구에 맡깁니다(#020).
  • Worker는 별도 파일로 배포하고 workerUrl 옵션을 둡니다. 인라인 빌드는 하지 않습니다.
  • 세그먼트는 JSON 헤더 한 줄 + 순수 JSON Lines입니다. 바이너리 프레임과 CRC32는 쓰지 않습니다(#016). 외부로는 tab, seq, 전역 context를 채운 JSONL을 내보냅니다.
  • 레코드 필드는 ts(Date.now()), lv, msg, ctx, err입니다. tab, seq, 전역 context는 헤더 줄에 둡니다.
  • 쓰기 경로(protocol.html): log() 때 JSON.stringify(#014) → 문자열 큐(#015) → 주기·크기·error 조건으로 flush(#017) → Worker가 쓰고 ack(#018). hidden과 pagehide 때도 flush(#020).
  • 과부하: 메인 버퍼 + 응답 안 온 양이 80%면 debug·info 거절, 100%면 전부 거절. 버린 건수는 flush 때 한 줄로 남깁니다(#019).
  • 같은 탭 subscribe()는 v0.1에 포함하고, flush 때 묶음을 넘깁니다(#023).
  • 숫자(flush 주기 200ms, 256K자, 4M자, 80%, 세그먼트 5분)는 초안이며 벤치마크로 정합니다. flush 주기는 "저사양 모바일에서 flush 비용 ≤ 메인 스레드 1%인 가장 짧은 간격"으로 고릅니다.
  • 공개 API(api.html): 모듈 싱글톤 init() + logger.info(msg, ctx?), setContext, flush, close, subscribe(디버깅용), exportLogs. query는 v0.1에 없습니다(#057). 실패한 logger는 메인 스레드에 부하를 주지 않습니다(#041).
  • 세그먼트를 닫고 새로 여는 것은 "로테이션", 새로 열지 않고 옮기기만 하는 것은 "pending으로 옮김"이라고 부릅니다(#037).
  • 압축은 보류합니다.

6단계(벤치마크 환경)에서 다룰 것

  • Vitest browser mode(Playwright) 구성. jsdom에는 OPFS, Worker, Web Locks가 없습니다(#005).
  • 초안 숫자를 정할 벤치마크: flush 주기와 크기(#017), 호출마다 encodeInto 여부(#014), 버퍼 상한과 80% 문턱(#019), 세그먼트 스캔(#016), subscribe 파싱(#042), 업로드 시간(#045)
  • 검증할 것 목록: architecture.html, storage-format.html, protocol.html, api.html

진행 방식

  • 질문은 한 번에 하나씩 합니다.
  • Lock 설계는 조건 없이 단순하게 둡니다. 모든 탭이 같은 규칙을 따르고, 탭 상태에 따라 달라지는 규칙을 만들지 않습니다(#022).
  • 구성 요소나 기능을 추가하기 전에 "정말 필요한가"를 먼저 따집니다.
  • 결정은 docs/decisions.md에 짧게, 설계 설명은 이 디렉터리의 HTML에 씁니다. 같은 내용을 두 곳에 쓰지 않습니다.
