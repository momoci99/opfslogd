지금까지 확정된 것 (요약)

  • 대상: 최신 데스크톱 + 모바일 브라우저. 초당 수천 건 이상. 목표 수치는 성능 목표 참고.
  • 탭마다 Dedicated Worker가 sync access handle로 자기 세그먼트에 씁니다. SharedWorker는 쓰지 않습니다.
  • 여러 탭 중 하나만 해야 하는 일(보존 정리, 업로드, 주인 없는 파일 복구)은 Web Locks로 조율합니다.
  • 업로드는 사용자가 넘기는 send() 콜백으로 합니다. resolve되면 done, reject되면 재시도합니다.
  • 세그먼트 상태: active → pending → done → 삭제. 용량을 넘으면 done부터, 그다음 오래된 pending부터 삭제합니다.
  • Worker는 별도 파일로 배포하고 workerUrl 옵션을 둡니다. 인라인 빌드는 하지 않습니다.
  • 세그먼트는 JSON 헤더 한 줄 + 순수 JSON Lines입니다. 바이너리 프레임과 CRC32는 쓰지 않습니다(#016, 4단계에서 #010을 고침). 외부로는 tab, seq, 전역 context를 채운 JSONL을 내보냅니다.
  • log()를 호출할 때 바로 JSON.stringify합니다(#014). 메인 스레드 버퍼는 문자열 배열 + 길이 카운터이고, flush마다 새 버퍼 하나를 Worker로 transfer합니다(#015).
  • 레코드 필드는 ts(Date.now()), lv, msg, ctx, err입니다. tab, seq, 전역 context는 헤더에 둡니다.
  • 압축은 보류합니다.

4단계에서 다룰 것

이전 단계에서 넘어온 항목도 포함합니다.

  • 버퍼에 담는 형태 → log() 때 직렬화 (#014), 링버퍼 대신 문자열 큐 (#015)
  • 프레임 헤더를 누가 만들지 → 프레임 헤더 제거 (#016)
  • flush 시점 → 200ms 타이머(데이터 있을 때만) + 256K자 + error(50ms 간격) (#017)
  • Worker 응답과 버퍼 상한 → flush마다 ack, 상한(초안 4MB)은 메인 버퍼 + 응답 안 온 양 (#018)
  • pagehide / visibilitychange 처리: 닫힐 때 최선의 flush, 세그먼트 봉인
  • 과부하 시 버리기: debug부터 버리고 error는 보존. 버린 건수를 레코드로 남기는 방식
  • 백그라운드에서 멈춘 탭의 Lock: 업로드 Lock을 쥔 채 멈추는 문제. 숨겨질 때 Lock을 내려놓는 방안 (업로드의 위험 항목)
  • 같은 탭 안 subscribe()를 어느 지점에서 호출할지 (flush 전 또는 후)

5단계 이후로 넘긴 것

  • 내보낸 JSONL에서 전역 context를 담는 필드 이름. init({ context }) 옵션 이름과 함께 정합니다.
  • 세그먼트 헤더 줄의 키 이름. 구현할 때 정합니다.
  • 검증할 것 목록: architecture.html, storage-format.html
